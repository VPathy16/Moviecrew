# v6 — after loop 6

## Thesis status
"Out of options" is false. Two tracks, stated with honest odds:
- Modest (likely, ~40–60% of reaching a good outcome): open action firewall → job / contract / acqui-hire / grant.
- Ambitious (unlikely, <5%, cheap to try if gated): an Android on-device profile of the existing agent-trust
  standards, adopted by a platform or card network.

## What loop 6 established
- The attestation handshake as v5 framed it proves identity, not behaviour; only ON-DEVICE agents can make
  hardware-backed claims (Android Key Attestation binds key ↔ package/signing cert/boot state). ADB-driven
  frameworks (droidrun, mobile-use) can't.
- Web agent trust is owned: IETF Web Bot Auth (Cloudflare+Google), Visa TAP, Mastercard Agent Pay, Google AP2
  (moved to FIDO May 2026; has an Android SDK), HUMAN/DataDome/Akamai; KYA money goes to Baselayer ($35M),
  Oak ($60M seed), Persona. Solo founder can't compete there.
- Mobile gap is real and unfilled: Play Integrity flags accessibility control with no "trusted agent" class;
  Android 17 Advanced Protection revokes non-accessibility-tool access; AppFunctions calling is privileged;
  Appdome's "Trusted AI-Assistants" is a spoofable package-name regex allow-list. Google privileges its own agent.
- Buyers today pay to BLOCK agents (banker malware +56% in 2025; Zimperium: 1,243 financial brands targeted).
  "Allow good agents" buyers arrive 2027+ and a platform will likely capture it.
- New buyer that exists NOW: MAS Singapore SAFR (3 Jul 2026) asks for "governance checkpoints that verify and
  record an AI agent's proposed actions before execution" — AgentGuard's executor firewall + audit log, for
  institutions' own agents.

## Best current answer
AgentGuard: an open action firewall for Android agents (executor-level rules, reconfirmation, reference-token
data tracking, tamper-evident log), positioned three ways:
1. Open source for agent builders — PR a generic `before_action` hook into droidrun/mobile-use; AgentGuard stays
   an external plugin. Kotlin enforcer for on-device agents (Operit, UNO).
2. Compliance: "SAFR-aligned runtime governance checkpoints" for fintechs/banks building their own mobile/RPA
   agents (MAS BuildFin.ai contributors).
3. Partnership wedge: PoC replacing Appdome's package-name allow-list with cryptographic verification of a
   guarded on-device agent's signed policy manifest (Key Attestation + Web Bot Auth "Signature Agent card"
   semantics). Publish as a spec draft / blog; post to IETF webbotauth list / FIDO payments WG.
