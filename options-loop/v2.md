## Corrected facts (primary source: Commission decision DMA.100220, 16 Jul 2026)
- 11 Android capabilities; 5 "Restricted" need certification (app-data access, context-aware intelligence,
  structured on-device integration/AppFunctions-type, screen automation, system integration).
- Criteria para 125: (b) honour/reconfirm user intent before sensitive irreversible actions; (c) hardening vs
  input/supply-chain/integration risks; (d) data only as necessary, minimise inadvertent disclosure, consent;
  (e) baseline mobile app security (likely MASA/MASVS); (f) developer processes & vuln monitoring.
- NO user threshold (the 50k MAU was about Search data). UNO itself can apply.
- Certifiers: Google's Trusted Certification Authorities programme; TCA applications 1 Feb 2027; assistants apply
  1 May 2027; Android 18 by 1 Aug 2027. Non-assistant "Qualified Services" can also be certified. Users can opt out.
- Likely TCAs: DEKRA, NowSecure, NCC, Applus+, SGS, TrustCB — already Google's MASA labs, and they co-signed
  Google's pro-gatekeeper post. A solo founder won't become a TCA.
- Outside the EU: AppFunctions calling is privileged; Play bans autonomous Accessibility agents; ROLE_ASSISTANT
  gives invocation, not action. Agentic power outside EU = OEM deals (Perplexity–Samsung) or nothing.
- Other jurisdictions: UK (choice screen only so far), Japan MSCA (possible), Brazil (bill), US (no interop).

## What was wrong with v1
- Sold to the wrong side: ~8 assistant vendors won't hand a regulatory gate to a solo SDK; certification attaches
  to an app build, not a library.
- Open-source + readiness consulting ends when vendors pass.
- One-regulation dependency = a "miracle" with a Brussels address.

## Best current answer: an agentic-behaviour conformance suite ("the test, not the SDK")
- Gap: MASA/MASVS labs test app security, not AGENT behaviour. No one found selling tests for criteria (b)(c)(d):
  intent-reconfirmation checks, prompt-injection / intent-hijack scenarios, data-disclosure probes during agent
  runs, audit-log evidence packs.
- Buyers (in order):
  1. The likely TCAs/labs (partner or license): they must test agent behaviour from 2027 and have no suite.
  2. Assistant applicants (per build, recurring: every release re-tested).
  3. OEMs doing Perplexity-style deals (non-EU vetting).
  4. Apps being CALLED by agents (AppFunctions / remote MCP servers): provider-side gating + tests — global,
     DMA-independent revenue (the old H2, re-aimed).
- UNO's role: open-source reference/testbed, and aim to be among the first certified Qualified AI Assistants
  (credibility, not a consumer business).
- Go-to-market: publish an open reference spec for criteria (b)/(d); comment on Google's Feb 2027 draft terms;
  approach TCAs now.

## Must be true / kill criteria
- Revenue that doesn't need the DMA: 2–3 paid pilots with apps exposing MCP servers within 90 days.
- ≥1 lab/TCA willing to pilot or license by 31 Jan 2027, else the DMA angle is dead.

## Top risks
Labs build it in-house; Google designs certification around its own APIs (system-rendered reconfirmation);
Google appeal/delay; buyers won't depend on a solo founder; EU-only if Google geofences.
