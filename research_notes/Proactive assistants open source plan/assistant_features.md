## 0. Status snapshot: what each product is, and what is announced vs available

### Takeaway
By October 2026 every major lab ships the same basic design: a persistent agent with its own cloud VM and browser, connectors, a schedule or event trigger, and an approval gate before sending, paying, signing or deleting. Most of these products are still waitlisted betas or research previews, limited to the US or to top-tier plans. Gemini (Tasks/Spark) is the only one already rolled out in India and native to Android. OpenClaw is the only open-source, self-hosted reference.

## 1. Proactivity: morning brief, check-in cadence, urgency, event triggers

### Takeaway
"Morning brief + periodic polling + alert only when something needs attention" is the consensus design (Duet, Gemini Daily Brief, Poke, Lindy). The leaders are moving from fixed polling to event triggers: Perplexity has Slack, Gmail, Outlook, Linear and GitHub triggers; Manus has email, Slack, Notion and calendar; Gemini has a flight-delay example; Grok Bot routines take event triggers; OpenClaw has webhooks, IMAP and MCP events. No vendor documents a real urgency model. They rely on the LLM's judgment plus a "stay silent" token or a notification threshold.

### Cited Findings
- **Claude Duet**
  - Each morning it reviews email and calendar, identifies priorities, and can start first steps such as drafting replies for review — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
  - During the day it sends updates on background work and follows up on threads that have gone quiet. It checks accounts "at set intervals" (unspecified), and urgent items may arrive between checks — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
  - Press reports the check interval as "every few hours". Anthropic says more frequent checks would use up limits much faster. After the brief it contacts the user only when something needs attention — [The Decoder](https://the-decoder.com/anthropic-takes-on-grok-bot-metas-muse-and-openais-dots-with-its-always-on-agent-claude-duet/) [press]; [MacRumors](https://www.macrumors.com/2026/10/21/anthropic-claude-duet/) [press]
  - Known weakness: it can misread a thread, misjudge urgency, or miss items that arrive between checks. Anthropic plans to tune outreach timing from tester feedback — [The Decoder](https://the-decoder.com/anthropic-takes-on-grok-bot-metas-muse-and-openais-dots-with-its-always-on-agent-claude-duet/) [press]
- **OpenAI Dots**
  - When not on a task, Dots run "proactive research" using read-only connections. In that mode a Dot "cannot send messages, modify content, or control the computer or browser" — [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]; [9to5Google](https://9to5google.com/2026/09/29/openai-dots-agent/) [press]
  - Examples: a Dot investigates bugs when they are mentioned in Slack, builds apps when a design is ready, and noticed an unsent invoice and drafted it for approval — [9to5Google](https://9to5google.com/2026/09/29/openai-dots-agent/) [press]
  - Supports event-triggered automations and recurring tasks on schedules or external events. Pages can check chosen sources at a chosen frequency — [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]
- **Meta Muse**
  - Responds to schedules and relevant events and decides whether new results warrant a notification. It can start conversations unprompted, and users can reduce, increase or disable this behavior. No frequency was given — [TestingCatalog](https://www.testingcatalog.com/meta-introduces-muse-as-a-proactive-personal-agent/) [3P/press]
  - It learns from conversations what matters to the user and makes unprompted suggestions — [TechCrunch](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/) [press]

- **Grok Bot**
  - Bots start work from a user message, a routine or external event, or a call from another Bot. Routines run "on a schedule or on an event trigger" — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P citing FAQ]
  - Notification policy is set separately from the schedule. Routines can save every check but message the user only past a defined threshold — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]
  - A "Primary Bot" is the single proactive Bot that handles everyday requests and checks in when blocked — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]

  - Daily Brief is a revival of "Daily Hub", which Google tried on Pixel 10 and pulled after poor feedback.   - Tasks can run at a set date and time "or in response to an event, such as a flight delay" — [Gemini Help (Android)](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]

- **Perplexity Computer**

  - Microsoft's examples include surfacing urgent emails each evening with draft replies prepared — via search snippet of [Business Standard](https://www.business-standard.com/amp/technology/tech-news/microsoft-agentic-copilot-tasks-unveiled-execute-tasks-in-background-explained-126022700385_1.html) [press]
- **Manus**

  - The docs say scheduled tasks are not suited to real-time monitoring — via search snippet of [Manus docs](https://www.manus.im/docs/features/scheduled-tasks) [primary]
- **Poke**
  - "Proactive, private, personal, and right in your texts." It uses connected services and memory to help "right on time" — [poke.com](https://poke.com) [primary]
  - Reviewers describe a morning overview, flight-change alerts, meeting pings and nudges on monitored email threads. Email filtering is called "noisy", with an estimated hit rate of about 7 in 10 — [Saner.ai](https://www.saner.ai/blogs/poke-reviews) [3P]
- **Lindy**
  - Example routines: a daily 8:00 AM brief, a Friday 12:00 PM report, and a Monday 8:01 AM competitor report. Event examples: drafting email "when a reply's needed" and meeting notes "after every meeting" — [lindy.ai](https://www.lindy.ai/) [primary]
- **OpenClaw**
  - Setup creates one "Proactive check" job that runs "every 30 minutes unless the provider supplies a different initial cadence". It uses the main conversation, waits for idle, and delivers to the owner's DM — [OpenClaw heartbeat docs](https://docs.openclaw.ai/gateway/heartbeat) [primary]
  - Silence protocol: the agent returns `NO_REPLY` when there is nothing to report, which needs no extra model call.   - Triggers: cron, authenticated webhooks, an IMAP email trigger (sender-gated, isolated reader sessions), internal hooks, and MCP Events — [OpenClaw automation docs](https://docs.openclaw.ai/automation) [primary]

### Inferences
- What to copy: (a) a once-daily brief; (b) a cheap periodic check with an explicit "silent" token (OpenClaw `NO_REPLY`) and quiet hours; (c) event triggers with filter conditions (Perplexity); (d) a notification threshold separated from the check schedule (Grok Bot). Together these address the "misjudged urgency" complaints logged against Duet and Poke.
- Duet's frank statement that more frequent checks burn quota shows the economic constraint: polling cadence is a cost knob. Perplexity's "no credits while watching for a trigger" is the better economic model, but it needs push or webhook sources.
- On Android, the OS notification stream is a unique trigger source. OpenClaw's Android node already forwards notifications (see section 4), which cloud-only rivals cannot match.

### Gaps
- No vendor publishes how "urgency" is scored. Duet's exact interval is unpublished ("set intervals" / "every few hours").
- No Muse or Dots morning-brief feature was confirmed. Copilot Tasks' trigger types were not found.

## 2. Scheduling: creation, limits, management UI, delivery

### Takeaway
Natural-language creation is universal. Form-based editing and record-a-demo ("teach a task") are the differentiators: Grok Bot has a 10-minute browser recording that becomes a draft skill. Published limits cluster around 10–15 concurrent schedules for consumers: ChatGPT allows 3–15 by plan, Gemini scheduled actions 10, Gemini Tasks 15 concurrent, and Grok Bot 50 routines per Bot. Results go to the originating thread plus push or email. Slack and Gmail drafts are the common external sinks.

### Cited Findings
- **ChatGPT scheduled tasks**
  - Active-task caps: 3 for Free and Go, 5 for Plus, 10 for Business and Edu, 15 for Pro and Enterprise. To go further, pause or delete a task or wait for one to finish — [OpenAI Help](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt) [primary, via search snippet]
  - Notifications are push, email or both, set in Settings → Notifications. On Android, creating a task from the phone triggers the notification-permission prompt. Manage via Settings → Notifications → Manage tasks, or click the task pill in the chat to edit, pause or delete — [OpenAI Help](https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt) [primary, via search snippet]
  - Scheduled agent runs draw on the monthly agent limit. A community bug report is titled "Scheduled tasks (Morning Briefing) consumed 100% of my 5-hour limit in background" — [OpenAI Community](https://community.openai.com/t/scheduled-tasks-morning-briefing-consumed-100-of-my-5-hour-limit-in-background-fix-this-bug/1396257) [user report]
- **OpenAI Dots**: recurring tasks and event automations exist (see section 1). The cap on routines was not found.
- **Claude Duet**
  - The **Tasks tab** shows active work and highlights items needing input. Duet posts to the main thread when a task finishes or needs a decision. Only the user can mark a task completed — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
  - Schedule limits and a recurring-task editor were not documented.
- **Gemini**
  - Scheduled actions launched in June 2025 for AI Pro and Ultra, with up to 10 active. Content is prepared in advance, so fast-changing data such as stock prices may be stale — [blog.google (Jun 2025)](https://blog.google/products-and-platforms/products/gemini/scheduled-actions-gemini-app/) [primary, via search snippet]; [Gemini Help: Schedule actions](https://support.google.com/gemini/answer/16316416?co=GENIE.Platform%3DAndroid&hl=en) [primary]
  - An Android form-style creator (a bottom sheet to name, describe and schedule) was found in an app build, with editing on Android lagging behind — [Android Authority](https://www.androidauthority.com/create-gemini-scheduled-actions-android-3646816/) [press, APK teardown]
  - Tasks (ex-Spark): start by tapping **Task**, then optionally add a schedule, reference a skill with @, or pick model and thinking level. Guided setup with "set up", "get started" or "interview me". Up to 15 tasks can run at once, and a schedule is skipped if 15 are already running. Pause or resume from the thread's scheduled-task chip. Task schedules are distinct from chat scheduled actions — [Gemini Help (Android)](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]
  - The Oct 2026 **Scheduled** page shows both Tasks and scheduled actions, grouped Active, Paused, Completed and Suggested. The history list filters by Ready, Needs attention and In progress — [9to5Google](https://9to5google.com/2026/10/12/gemini-spark-task-redesign/) [press]
- **Grok Bot**
  - A routine is "a schedule that runs a saved skill" — [docs.x.ai FAQ](https://docs.x.ai/grok-bot/faq) [primary, via search snippet]
  - Limits: 50 routines per Bot, with the 20 most recent runs kept. Deletion is irreversible, and every run consumes usage even when nothing is found. Teach-a-task records a browser workflow of up to 10 minutes, without audio, and turns it into a draft skill for review; rollout is gradual. Editing schedules and teaching workflows require the desktop app. Routines report to the owner's chat or can post to Slack — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]
  - A user can demonstrate a workflow and the Bot saves it as a routine, with corrections added over time — [VentureBeat](https://venturebeat.com/orchestration/spacexais-grok-bot-turns-agents-into-persistent-digital-coworkers-that-can-operate-your-apps-for-120-per-month) [press]
- **Perplexity Computer**
  - Created in natural language in the omnibar or via Automations → New Automation. The dashboard shows instructions, status and run history, including what triggered each run and what was produced. Automations can be edited and paused. Output goes to destinations such as a Slack channel or a Gmail draft — [Perplexity blog](https://www.perplexity.ai/hub/blog/computer-adds-automations-for-ongoing-work) [primary]
  - Lapsed connector authorization brings up a reconnect prompt. Repeated connector failures pause a task, and it does not restart on its own — [Perplexity Help: Scheduled Tasks](https://www.perplexity.ai/help-center/en/articles/11521526-perplexity-tasks) [primary, via search snippet]
- **Manus**
  - Scheduled Tasks 2.0: each run can continue in the same task or start a new one. Trusted workflows can "skip confirmations". Schedules can attach to a Project (shared files, skills, connectors, instructions). Manus-built web apps can run their own scheduled actions. Side-panel, schedule and calendar views show upcoming and past runs, and an edit screen adjusts prompt, timing and settings — [Manus blog](https://manus.im/blog/manus-schedules) [primary]
- **Copilot Tasks**: tasks are described in plain language and run once, on a schedule or recurring. A report is delivered when finished, and users can pause or cancel — via search snippets of [Neowin](https://www.neowin.net/news/microsoft-introduces-copilot-tasks-a-new-way-to-get-things-done-using-ai) and [Business Standard](https://www.business-standard.com/amp/technology/tech-news/microsoft-agentic-copilot-tasks-unveiled-execute-tasks-in-background-explained-126022700385_1.html) [press]
- **Poke**: automations are described in plain language or picked from community "recipes", which are shareable. Settings and automations live on a web dashboard. Results arrive as texts — [Saner.ai](https://www.saner.ai/blogs/poke-reviews) [3P]; [poke.com](https://poke.com) [primary]
- **Lindy**: "+ New routine — a sentence is all it takes" — [lindy.ai](https://www.lindy.ai/) [primary]
- **OpenClaw**: Automations offer one-shot (`--at`), interval and cron expressions. Each job has its own schedule, context, delivery policy (chat channel or webhook) and run history. CLI: `openclaw automations list --all`. Daily reports run in isolated execution — [OpenClaw automation docs](https://docs.openclaw.ai/automation) [primary]

### Inferences
- Minimum viable scheduler: natural-language creation (with a form fallback), a cap of about 10–15 active jobs, a per-job run history, pause and resume, and a "same thread vs new thread per run" choice (Manus). Add a "Suggested" automations feed (Gemini) and recipe or template sharing (Poke, Grok Bot).
- Teach-by-demonstration exists only in Grok Bot (desktop browser). An Android accessibility-service recorder could be a differentiator for an Android OSS app, which is an inference with no product precedent on mobile.

### Gaps
- Dots' and Muse's schedule limits and UI, Copilot Tasks' limits, Lindy's routine limits, and Poke's automation limits were not found.

## 3. Agents and conversations: single vs multiple agents, threads, handoffs, group chats

### Takeaway
There are two camps. One is single persona with one main thread: Duet, Muse, Poke and Gemini, with Duet and Muse adding side channels or chats. The other is a roster of named agents with group chats and handoffs: Grok Bot (up to 50 Bots, a Primary Bot, group chats), Manus Cue, OpenClaw (multi-agent routing plus a coordinator/specialist "team" preset), and Dots ("teams of Dots" announced but not shipped).

### Cited Findings
- **Claude Duet**: one main thread persists across sessions. Separate channels can be started for other topics and share the same memory. Tasks are assigned by text or voice — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]; [The Decoder](https://the-decoder.com/anthropic-takes-on-grok-bot-metas-muse-and-openais-dots-with-its-always-on-agent-claude-duet/) [press]. - **OpenAI Dots**

Users can @mention a Dot to take the next step — [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]
  - Specialist Dots have their own organizational identity, credentials and tools (pilot) — [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]
- **Meta Muse**: centers on one persistent conversation, with side chats for complex projects. Users can interrupt or queue several tasks. A Goals tab tracks tasks and plans — [TestingCatalog](https://www.testingcatalog.com/meta-introduces-muse-as-a-proactive-personal-agent/) [3P/press]. It can launch concurrent subagents internally — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]. Name, avatar and communication style are user-set — [TechCrunch](https://techcrunch.com/2026/09/08/meta-debuts-its-muse-ai-agent-will-consumers-trust-it/) [press]
- **Grok Bot**
  - Multiple role-based Bots (e.g. Sales Outbound, Expense Manager, Chief of Staff) run in parallel. They message each other, share context, transfer ownership of work, and can sit in group conversations. The interface is messaging-style, with the same conversation continuing across phone and desktop — [VentureBeat](https://venturebeat.com/orchestration/spacexais-grok-bot-turns-agents-into-persistent-digital-coworkers-that-can-operate-your-apps-for-120-per-month) [press]

In group chats the Bots decide who answers unaddressed messages, and the host wakes members in turn. Recommended handoff format: output path, completed work, evidence, open questions, next owner. A "workforce-checker" Bot can nudge stalled Bots. Duplicating a Bot copies its profile, skills and routines but not its memory — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]

- **Gemini**: each task has its own thread. The unified history mixes chats and tasks — [9to5Google](https://9to5google.com/2026/10/12/gemini-spark-task-redesign/) [press]; [Gemini Help](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]. "Custom sub-agents" were announced at I/O for later in 2026 — [blog.google](https://blog.google/innovation-and-ai/products/gemini-app/next-evolution-gemini-app/) [primary]

- **Manus Cue**: each agent gets its own email address, phone number, wallet and computer. Several agents can share a group chat, work toward a common goal and hand work to each other — [The Next Web](https://thenextweb.com/news/manus-2-0-cue-ai-agents-email-phone-wallet) [press]. - **Poke**: single assistant per phone number, single-user only with no team support — [Saner.ai](https://www.saner.ai/blogs/poke-reviews) [3P]

### Inferences
- For a consumer Android app, the safest default is the Duet/Muse shape: one primary agent and one main thread, plus topic channels or side chats that share memory. A Grok-style roster (Primary Bot plus specialists plus group chat) can be an advanced mode. OpenClaw's bindings and team preset are a ready OSS reference for implementing it.
- Grok Bot's structured handoff note (output, evidence, open questions, next owner) is worth copying verbatim as an inter-agent message schema.

### Gaps
- No vendor documents how a single-thread agent keeps parallel tasks from interleaving in the UI, beyond Duet's Tasks tab and Gemini's per-task threads.

## 4. Execution environment: cloud VM vs on-device vs local; keeps working when the device is off

### Takeaway
Every commercial product now runs on a vendor-hosted cloud VM or browser that keeps working with the phone off. Several optionally reach the user's own computer: Dots, Grok Bot, Gemini (local Chrome), Manus Remote Control, and Perplexity's Mac-mini Personal Computer. Gemini on Android is the only one that also automates native phone apps on-device, via a "secure virtual window" and AppFunctions. OpenClaw is the inverse: it runs on the user's own host, with the phone as a sensor/actuator node.

### Cited Findings
- **Claude Duet**: own cloud computer with a browser, so it keeps working after the app closes. For sites without a connector it uses its cloud browser. Users "can't watch the browser or take it over". It cannot see all projects or files on the user's computer — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
- **OpenAI Dots**: each Dot has its own cloud computer and browser that the user can watch at any time. A Dot can be granted permission to use the user's own computer — [9to5Google](https://9to5google.com/2026/09/29/openai-dots-agent/) [press]; [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]
- **Meta Muse**: each user gets a dedicated cloud Linux VM split into two isolated security domains. The agent runs in a `systemd-nspawn` cell with filtered syscalls. Separate host services handle classifiers, connector workers and credentials (`hatch-authd`). Data is continuously backed up — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]. Users can watch its browser — [Wikipedia](https://en.wikipedia.org/wiki/Muse_(AI_agent)). A "Muse Confidential VM" is planned but not launched — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]
- **Grok Bot**: one persistent managed Linux VM per user, shared by all of that user's Bots. Each Bot has its own screen, but files, cookies and credentials are shared ("Bots are not separate security boundaries"). An option routes egress through the user's desktop IP. Local-computer access is off by default and asks every time — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]
- **Gemini Tasks**
  - On mobile it uses a **remote (cloud) browser** that keeps working when the device is closed and saves cookies, plus a **remote computer** for code execution. On desktop it can use local Chrome with the user's signed-in sites — [Gemini Help](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]
  - Android app automation (beta, Feb 2026, Pixel 10 and Galaxy S26, US and Korea) runs apps in a "secure, virtual window on your phone" that users can watch, stop or take over. It never presses the final pay or place-order button — [9to5Google](https://9to5google.com/2026/02/25/gemini-automation-android/) [press]; [9to5Google (Mar 2026)](https://9to5google.com/2026/03/12/gemini-android-app-automation-galaxy-s26-rollout/) [press]
  - **AppFunctions**, an MCP-like Android API through which apps expose functions to agents, was in private preview as of May 2026 — [9to5Google](https://9to5google.com/2026/02/25/android-appfunctions-gemini/) [press]; [Android Developers](https://developer.android.com/ai/appfunctions) [primary]
  - "Gemini Intelligence" (announced May 2026) is cross-app and web automation, opt-in per app, with on-device Gemini Nano for simple requests and cloud for heavier ones. It arrives "this summer" on Pixel and select Galaxy phones — [Android Authority](https://www.androidauthority.com/gemini-intelligence-3665302/) [press]
- **Perplexity**: Computer runs in a cloud sandbox, and scheduled tasks run in the cloud so the laptop can be closed — [Perplexity Help](https://www.perplexity.ai/help-center/en/articles/11521526-perplexity-tasks) [primary, via search snippet]. Personal Computer runs 24/7 on a dedicated Mac mini connected to local apps — [Perplexity blog](https://www.perplexity.ai/hub/blog/everything-is-computer) [primary]
- **Copilot Tasks**: uses "its own computer and browser" on Microsoft's cloud, so it does not need full device access — [Cloud Wars](https://cloudwars.com/ai/microsoft-copilot-tasks-microsoft-pushes-copilot-from-chatbot-to-personal-ai-agent/) [press]; Business Standard (via search snippet)
- **Manus**: a purchasable Cloud Computer keeps running after the laptop closes. **Remote Control** lets the user ask Manus from a phone to work on their computer and watch the desktop live — [The Next Web](https://thenextweb.com/news/manus-2-0-cue-ai-agents-email-phone-wallet) [press]
- **OpenClaw**
  - The Gateway runs on macOS, Linux, Windows (native or WSL2) or a VPS. Companion apps exist for Linux, Windows, macOS, iOS and Android — [OpenClaw platforms](https://docs.openclaw.ai/platforms) [primary]
  - **The Android app is a companion node, not a host.** It "requires a running OpenClaw Gateway" elsewhere, connects over WebSocket (`wss://` for remote use, e.g. Tailscale Serve), and keeps a foreground service alive — [OpenClaw Android docs](https://docs.openclaw.ai/platforms/android) [primary]
  - Android node commands: `camera.snap`/`clip`, `notifications.list`/`actions` (forwarded as events, with allow/block filters, quiet hours, 20/min rate limit; WhatsApp, Telegram, Discord and Signal notifications always excluded), `photos.latest`, `contacts.search`/`add`, `calendar.events`/`add`, `callLog.search`, `sms.search` (no send), `motion.activity`/`pedometer`, `device.*`, plus a Wear OS companion — [OpenClaw Android docs](https://docs.openclaw.ai/platforms/android) [primary]
  - Optional Docker sandbox per agent (`sandbox.mode`, `scope: "agent"`); otherwise the workspace "is not a hard sandbox" — [OpenClaw multi-agent docs](https://docs.openclaw.ai/concepts/multi-agent) [primary]

### Inferences
- An OSS Android assistant can follow two patterns. (1) **OpenClaw**: phone as node, with the brain on a home server or VPS. This keeps working with the phone off only if the server is always on. (2) **Gemini**: on-device app automation via Accessibility or AppFunctions. This does not run with the phone off, but it reaches native apps that cloud VMs cannot.
- A hybrid design fits Android: on-device triggers (notifications, SMS, calendar) feeding a cloud or self-hosted agent loop. No commercial product except OpenClaw exposes phone-local signals such as notifications or the call log to the agent.

### Gaps
- Dots' Android client behavior and Copilot Tasks' mobile support were not found. It is unclear whether Gemini Intelligence cross-app automation reached India.

## 5. Approvals and safety: what needs approval, how approvals look, takeover, classifiers, spending limits

### Takeaway
Approval categories converge: send or communicate, pay or purchase, sign, delete, publish, change permissions, sign in. The UI differs. Muse uses a dialog outside the chat, routed to a separate "Sentinel" agent. Perplexity and Grok Bot offer allow once / allow for thread / always allow / deny. Duet defers the approval while finishing the rest of the task. Payments are standardizing on Stripe Link single-use virtual cards (Duet, Muse, Grok Bot). Password, 2FA and CAPTCHA handling is either takeover of the cloud browser (Grok Bot, Gemini) or a secure on-device form that injects credentials without the model seeing them (Duet, Muse, Dots).

### Cited Findings
- **Claude Duet**
  - Asks before sending messages, making payments, signing documents or deleting anything, and shows what it is about to do. If the user can't approve right away, it finishes the rest of the task and brings the approval back later. Summaries cite the source email, file or spreadsheet — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
  - Hard-blocked even with approval: trading securities, moving money between accounts, accessing someone else's account. It cannot make phone calls or send texts — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
  - Passwords are typed into a separate on-device form that sends them directly to the browser, kept out of the chat. Email and web content is treated as information, not instructions, and the article acknowledges prompt injection risk — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
  - Press reports a dedicated classifier plus system-prompt rules that screen for sensitive data. It refuses to share card numbers or ID details, and health or finance data passes only when the user explicitly asks — [The Decoder](https://the-decoder.com/anthropic-takes-on-grok-bot-metas-muse-and-openais-dots-with-its-always-on-agent-claude-duet/) [press]; [MacRumors](https://www.macrumors.com/2026/10/21/anthropic-claude-duet/) [press]. The help center does not describe a classifier.
  - Purchases go through Link (Stripe) or Shop Pay with a one-time card per approved purchase — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
- **OpenAI Dots**: Custom Rules can permit, require approval for, or prohibit actions. An Activity View shows background work. An auto-review system checks consequential actions against instructions, rules and safety requirements to decide if approval is needed. Saved credentials work without exposing the password to the model, and changing passwords is reserved for the human — [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]; [9to5Google](https://9to5google.com/2026/09/29/openai-dots-agent/) [press]. Launch context: NBC reported safety questions — [NBC News](https://www.nbcnews.com/tech/tech-news/openai-launches-dots-ai-agents-safety-questions-rcna600338) [press, via search snippet]
- **Meta Muse**
  - **Sentinel**, a separate host-side agent, is the sole authority for connector actions and network egress. It returns allow, deny or ask. Grant scopes: one-time, session, task, time-bounded or perpetual. Approvals appear "in a dialog in the client UI, not in the chat", and the answer goes directly to Sentinel. Grants are bound to an exact connector or destination and use case — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]
  - "Tainted egress": kernel data-flow tracking removes auto-allow from processes that read user data — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]
  - Classifiers: the email connector filters OTPs, password-reset links and magic links. Browser classifiers flag unrelated personal data leaving the browser and high-risk form submissions. An ensemble of prompt-injection classifiers runs on external data. The browser sub-agent sees an accessibility tree, cannot run JS, and pauses during takeover or credential entry — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]
  - Payments: every payment needs approval. Each uses a single-use card bound to one merchant, one amount and a limited time window (Stripe Link; Shop Pay coming) — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]
  - Approval cards offer accept or reject. A full activity log lists actions and approved permissions — [TestingCatalog](https://www.testingcatalog.com/meta-introduces-muse-as-a-proactive-personal-agent/) [3P/press]
  - Incidents: Amazon blocked Muse on 21 Sep 2026, saying it did not identify itself and appeared to capture credentials. 404 Media reported human call-center workers completing some "automated" calls during beta. Shared chats were discoverable via DNS in Oct 2026, and Meta suspended sharing — [Wikipedia](https://en.wikipedia.org/wiki/Muse_(AI_agent))
- **Grok Bot**
  - Consequential actions (send, publish, purchase, delete, permission or production changes, legal terms) need approval. Options are Allow once, Deny, or an always-allow rule. Auto-review rules can be Require Approval or Always Allow, and Require Approval wins on conflict — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]; [docs.x.ai FAQ](https://docs.x.ai/grok-bot/faq) [primary, via search snippet]
  - **Computer takeover** for passwords, passkeys, 2FA codes, CAPTCHAs and payment confirmations. A secure credential request masks values out of the transcript and model context — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]; [docs.x.ai FAQ](https://docs.x.ai/grok-bot/faq) [primary, via search snippet]
  - Stripe Link purchase approval shows merchant, total and description, and issues a single-use card. US-only — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]
  - Bots learn over time when to ask and when to proceed — [VentureBeat](https://venturebeat.com/orchestration/spacexais-grok-bot-turns-agents-into-persistent-digital-coworkers-that-can-operate-your-apps-for-120-per-month) [press]
- **Gemini Tasks**
  - Confirmation is required before sending communications, changing or deleting data, purchases or financial transactions, submitting web forms, or signing in with Google. Sharing sensitive info (health, financial, government ID) needs permission. Editing shared Docs, Sheets or Slides needs review. Bulk actions on private Google Tasks need no confirmation. Each browsing task asks for confirmation first. A denial stops Gemini from trying another route — [Gemini Help](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]
  - Takeover: **View live → Take control → End control** on Android; "Take over task" and "Go back to Gemini" on web. If "Sign in with Google" isn't available, the user takes over to sign in — [Gemini Help](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]
  - Android screen automation never presses the final pay or order button — [9to5Google](https://9to5google.com/2026/02/25/gemini-automation-android/) [press]. Purchases via Agent Payments Protocol (AP2) are "coming" — [Android Authority](https://www.androidauthority.com/google-gemini-neural-expressive-gemini-spark-daily-brief-omni-updates-3668384/) [press]
- **Perplexity**
  - Per-connector-tool settings: Always allow, Always ask, Never allow. On a pause the user can approve one action, allow for the rest of the thread, or deny. Recurring runs inherit thread-level grants — [Perplexity changelog](https://www.perplexity.ai/changelog/computer-in-email-gpt-5-6-terra-luna-and-grok-4-6) [primary]
  - Automations let the user specify which actions need review — [Perplexity blog](https://www.perplexity.ai/hub/blog/computer-adds-automations-for-ongoing-work) [primary]. Personal Computer: sensitive actions need approval, sessions have a full audit trail, and there is a kill switch — [Perplexity blog](https://www.perplexity.ai/hub/blog/everything-is-computer) [primary]
  - Spending: monthly spending cap, default $200, adjustable up to $2,000 — [Sentisight / getsliq](https://www.sentisight.ai/how-much-perplexity-computer-cost/) [3P, via search snippet]
- **Copilot Tasks**: asks for consent before sending messages or making payments, and users can pause or cancel — [Cloud Wars](https://cloudwars.com/ai/microsoft-copilot-tasks-microsoft-pushes-copilot-from-chatbot-to-personal-ai-agent/) [press]
- **Manus**: "Skip confirmations" lets trusted scheduled workflows send, publish or post without approval — [Manus blog](https://manus.im/blog/manus-schedules) [primary]. Cue agents pay "within a budget the user sets" — [The Next Web](https://thenextweb.com/news/manus-2-0-cue-ai-agents-email-phone-wallet) [press]
- **Poke**: no approval step is described by reviewers. SOC 2 Type II and CASA Tier 2 certified — [Saner.ai](https://www.saner.ai/blogs/poke-reviews) [3P]
- **Lindy**: "Nothing irreversible happens without your approval." Demo responses include inline action buttons. Admins can set per-person spend caps — [lindy.ai](https://www.lindy.ai/) [primary]
- **OpenClaw**
  - Exec approval modes: `deny`, `allowlist`, `ask`, `auto` (a reviewer can allow, deny or escalate to a human), and `full`. On macOS an approval panel shows agent, host, command and working directory, with **Allow Once** (Cmd-Return; Return alone does not approve) and **Always Allow Here**. iOS and Android apps can act as approval clients. Matrix uses reactions ✅ / ♾️ / ❌ with `/approve` as fallback. Timeouts fall back to `askFallback` (default deny). Grants can expire (`grantExpiryDays`). `strictInlineEval` gates `python -c` and similar — [OpenClaw exec approvals](https://docs.openclaw.ai/tools/exec-approvals) [primary]
  - Chat channels never receive automation approvals. Approval-scope summaries (recipients, amounts) are display-only — [OpenClaw exec approvals](https://docs.openclaw.ai/tools/exec-approvals) [primary]
  - The team preset's role instructions require human approval before external sends, publishing, purchases, deletion or production changes — [OpenClaw multi-agent docs](https://docs.openclaw.ai/concepts/multi-agent) [primary]
  - Security history: Cisco found a third-party skill doing data exfiltration and prompt injection. In March 2026 Chinese authorities restricted state bodies from running OpenClaw — [Wikipedia](https://en.wikipedia.org/wiki/OpenClaw)

### Inferences
- A copyable approval spec for Android:
  - Fixed "always ask" categories: send, pay, sign, delete, publish, sign-in, sensitive-data share, form submit.
  - Per-tool policy: allow / ask / never.
  - Grant scopes: once / thread / task / time-bounded / always (Muse, Perplexity).
  - Approval cards outside the chat transcript, so injected text can't fake them (Muse).
  - Deferred approvals that don't block the rest of the task (Duet).
  - Hard-deny list: money movement, trading, others' accounts (Duet).
  - Android adds what cloud rivals can't: BiometricPrompt on approve-to-pay, and an on-device credential form that injects secrets into the agent's browser.
- Takeover of the agent's browser for 2FA or CAPTCHA (Grok Bot, Gemini) is table stakes. Duet's lack of takeover is a noted limitation.

### Gaps
- No vendor publishes its sensitive-data classifier's thresholds. Biometric confirmation was not documented by any product. Per-task spending caps were found only for Manus Cue (budget) and Perplexity (monthly cap, 3P).

## 6. Memory: per-agent vs shared, user-editable, how surfaced

### Takeaway
The trend is file-based, user-inspectable memory: Muse Memory files, Lindy `memory.md`, OpenClaw workspace files and "Memory Wiki", and Grok Bot per-Bot memory. Duet and Gemini instead reuse the account-wide chat memory and search ("Personal Intelligence", "Search and reference chats").

### Cited Findings
- **Claude Duet**: uses the memory, skills and connectors from the user's Claude account. It searches Duet chats and Claude chats outside projects, governed by the "Search and reference chats" setting. Memory from past conversations is kept after disconnecting an app — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
- **OpenAI Dots**: learns preferences, standards and habits from feedback. A Dot keeps "private notes to itself", and OpenAI says it does not train directly on proactive research or those notes. In ChatGPT Space, sharing a Page doesn't expose personal memory, but memory written onto a Page becomes visible to collaborators — [VentureBeat](https://venturebeat.com/technology/openai-launches-dots-always-on-ai-agent-coworkers-and-chatgpt-space-where-they-can-collaborate-with-human-teams) [press]
- **Meta Muse**: users can inspect, edit and download their files, including Muse's memory about them — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]. Memory files are editable. Forget tries to remove specific info, and Reset wipes history, files and active tasks. Deleting a chat doesn't necessarily delete its memories — [TestingCatalog](https://www.testingcatalog.com/meta-introduces-muse-as-a-proactive-personal-agent/) [3P/press]; Forget/Reset per search snippet of [rywalker.com](https://rywalker.com/research/meta-muse) [3P]. Training on queries is on by default with opt-out — [Wikipedia](https://en.wikipedia.org/wiki/Muse_(AI_agent))
- **Grok Bot**: each Bot has its own conversation and memory. Team Bots have team memory (saved only on request) plus private per-person notes. Duplicating a Bot doesn't copy its memory. The FAQ advises checking the current source rather than memory for important decisions — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]; [docs.x.ai FAQ](https://docs.x.ai/grok-bot/faq) [primary, via search snippet]
- **Gemini Tasks**: uses Personal Intelligence, meaning memory of past chats, saved instructions and connected apps. It requires Keep Activity on and opt-in to Personal Intelligence — [Gemini Help](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]
- **Perplexity**: Computer-in-Email replies use the sender's own connectors, permissions and **Memory** — [Perplexity changelog](https://www.perplexity.ai/changelog/computer-in-email-gpt-5-6-terra-luna-and-grok-4-6) [primary]. Each Automation run "builds on prior work" — [Perplexity blog](https://www.perplexity.ai/hub/blog/computer-adds-automations-for-ongoing-work) [primary]
- **Manus**: Projects provide shared files, skills, connectors and instructions reused by schedules — [Manus blog](https://manus.im/blog/manus-schedules) [primary]
- **Poke**: long-term conversational memory, with no searchable notes or task list — [Saner.ai](https://www.saner.ai/blogs/poke-reviews) [3P]
- **Lindy**: memory is stored in plain files (`memory.md`, `.index.md`) that the user can open and edit like a doc — [lindy.ai](https://www.lindy.ai/) [primary]
- **OpenClaw**: built-in memory searches only each agent's own memory, and cross-agent memory search was removed. Memory Wiki uses one global vault by default; `vault.scope: agent` gives per-agent vaults. `memory.search.extraPaths` adds shared reference material. Standing orders live in `AGENTS.md` and are injected into every session — [OpenClaw multi-agent docs](https://docs.openclaw.ai/concepts/multi-agent) [primary]; [OpenClaw automation docs](https://docs.openclaw.ai/automation) [primary]

### Inferences
- Copy the Lindy/OpenClaw/Muse pattern: Markdown memory files the user can read and edit in-app, per-agent by default with an opt-in shared vault, plus explicit Forget and Reset. Show where each fact came from, as Duet does for summaries.

### Gaps
- How Duet or Dots surface memory edits in the UI was not documented.

## 7. Connectors: MCP support, integration counts, custom connectors, OAuth handling

### Takeaway
Integration counts are marketing-sized: Duet 6,000+ (Claude Marketplace connectors and plugins), Dots 4,000+ (plugins), Lindy 1,500+, Gemini ~Workspace plus partners, Poke ~24 shown. MCP is explicit for Gemini (Canva, OpenTable, Instacart), Lindy (any hosted MCP server), Poke (custom MCP), Grok Bot ("plugins similar to MCP"; custom MCP servers) and OpenClaw (MCP Events). ### Cited Findings
- **Claude Duet**: 6,000+ connectors and plugins from the Claude Marketplace — [The Decoder](https://the-decoder.com/anthropic-takes-on-grok-bot-metas-muse-and-openais-dots-with-its-always-on-agent-claude-duet/) [press]; Reuters via [Investing.com](https://www.investing.com/news/stock-market-news/anthropic-unveils-claude-duet-ai-agent-app-4964042) [press, via search snippet]. Help-center list: Gmail, Google Calendar, Google Drive, Slack (with limits), QuickBooks, HubSpot, Docusign, Calendly, plus a Stripe connector and plugins such as "small business". Microsoft 365 is not available yet. The user starts every connection — [Claude Help Center](https://support.claude.com/en/articles/17631495) [primary]
- **OpenAI Dots**: 4,000+ apps via OpenAI's plugin ecosystem. Access is controlled through existing ChatGPT app controls. - **Meta Muse**: apps are connected one at a time. Built-in connectors cover email, calendar, payments, health and fitness, smart home, dining, shopping, music and events. Muse can use user-supplied credentials for public APIs without a connector, and the browser where there is no API. Read and write are separated, and users can strip permissions finer than the OAuth scopes — [Meta Research blog](https://research.meta.ai/blog/security-and-safety-for-ai-agents-our-approach-with-muse) [primary]
- **Grok Bot**: plugins are "structured connectors, similar in concept to MCP servers", mentioned with @. Named: Google Docs, Sheets, Slides, Gmail, Notion, GitHub, Slack, an X plugin, and Plaid finance (read-only). Connector API keys go into a secure field and the Bot never sees the raw key. Custom MCP servers are supported but not copied into templates — [flaviocopes](https://flaviocopes.com/grok-bot/) [3P]. Tasks connect to Workspace (Calendar, Docs, Drive, Gmail, Keep, Sheets, Slides, Tasks), Google services (Contacts, Notebook, Photos, YouTube, Search, Finance, Flights, Hotels, Maps), several third-party apps and **custom apps** — [Gemini Help](https://support.google.com/gemini/answer/16596215?hl=en&co=GENIE.Platform%3DAndroid) [primary]. A third-party claim of "30+ apps" is unverified — [MindStudio](https://www.mindstudio.ai/blog/what-is-gemini-spark-google-24-7-agent) [3P, via search snippet]
- **Perplexity**: Gmail, Slack, Salesforce, Snowflake, HubSpot, Microsoft 365 (SharePoint, OneDrive) and "hundreds of other platforms", with 40+ live finance tools. Admins can disable connectors org-wide — [Perplexity blog](https://www.perplexity.ai/hub/blog/everything-is-computer) [primary]; [Perplexity changelog](https://www.perplexity.ai/changelog/computer-in-email-gpt-5-6-terra-luna-and-grok-4-6) [primary]
- **Copilot Tasks**: "No manual connection to MCPs or similar tools is required" — [Cloud Wars](https://cloudwars.com/ai/microsoft-copilot-tasks-microsoft-pushes-copilot-from-chatbot-to-personal-ai-agent/) [press]
- **Poke**: about 24 integrations shown (Gmail, GCal, Outlook, Notion, Asana, Linear, Todoist, GitHub, Vercel, Supabase, Sentry, Strava, Fitbit, Sonos, Hue, Canva and others). Custom integrations through "Poke Kitchen" — [poke.com](https://poke.com) [primary]. Custom MCP servers are supported, but third-party and MCP calls can be slow. No Google Docs — [Saner.ai](https://www.saner.ai/blogs/poke-reviews) [3P]
- **Lindy**: 1,500+ integrations, "any hosted MCP server", and it builds its own integration if neither exists — [lindy.ai](https://www.lindy.ai/) [primary]
- **OpenClaw**: channel plugins and skills via the ClawHub marketplace. An MCP Events automation source exists — [docs.openclaw.ai](https://docs.openclaw.ai/) [primary]; [OpenClaw automation docs](https://docs.openclaw.ai/automation) [primary]. Cisco found a malicious third-party skill and noted inadequate vetting — [Wikipedia](https://en.wikipedia.org/wiki/OpenClaw)

### Inferences
- For OSS: adopt MCP as the connector standard (Gemini, Lindy, Poke, Grok Bot and OpenClaw all accept it), plus a cloud or headless browser fallback. Store OAuth tokens in a credential broker that injects them at egress, never in model context (Muse `hatch-authd` pattern). Treat a skill or plugin marketplace as a supply-chain risk (ClawHub incident).
- On Android, consider exposing on-device AppFunctions as MCP-like tools, since Google is positioning AppFunctions as "MCP-like" for Android.

### Gaps
- Exact MCP support for Duet, Dots and Muse was not documented (Duet presumably inherits Claude connectors). The Gemini third-party connector count was not found.
