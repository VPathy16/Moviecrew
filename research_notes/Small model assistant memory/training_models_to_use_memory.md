# Training a small (~2B) model to reliably use retrieved memory notes (Maya / Hanu v4)

Scope note: this file covers the reading and use of notes that are already retrieved (fine-tuning data design, note wording, distractors, conflicts, abstention, dodges, data size and distillation). It does not cover memory storage or retrieval ranking. "Retraining" below means a new SFT/DPO round. "Block change" means changing the MEMORY NOTES / QUESTION / MODE / AUDIO_ROUTE / USER / TOOLS structure or the plan grammar, which would also need retraining. "Wording only" means changing the text inside the 1-5 note lines, which the brief allows without retraining (though the model's behaviour on new wordings must be re-measured, because it was trained on the old ones).

## 1. What the literature says about training models to ground answers in provided context (RAFT, Self-RAG, RA-DIT, ChatQA, robustness to irrelevant context, abstention), with data mixes and measured effects

### Takeaway
Every method that worked trained on a deliberate mix: examples where the answer is in the context alongside distractors, examples where the context has only distractors or is missing the answer (the target is a fixed abstention phrase), and general instruction data so the model keeps its base skills. Small amounts are enough: about 1,000 robustness examples, about 1,500 unanswerable turns, and up to about 19k DPO pairs for grounded refusal. Too much abstention data hurts answering, so the abstain share should be tuned on a held-out set rather than maximised.

### Cited Findings
**RAFT (Zhang et al., UC Berkeley, Mar 2024; LLaMA2-7B)**
- Recipe: for P% of training questions the context is the golden document plus distractors; for the remaining (1−P)% it holds only distractors. The default setup is 1 golden document plus 4 distractors. Answers are chain-of-thought ("##Reason: ... ##Answer: ...") with verbatim quotes from the context wrapped in ##begin_quote## / ##end_quote##, and the CoT was generated by GPT-4-1106. — [RAFT, arXiv 2403.10131](https://arxiv.org/html/2403.10131)
- The best P depends on the dataset ("ranging from 40%, 60%, and 100%"); the authors say P=80% "appears to enhance the model's performance". Training on golden documents only "frequently results in inferior performance". — [RAFT](https://arxiv.org/html/2403.10131)
- Best number of training distractors: golden doc + 3 distractors for NQ and + 1 for HotpotQA, evaluated with top-3 retrieval. The figure caption (4/3/2 docs for NQ/TriviaQA/HotpotQA) does not fully agree with the text. — [RAFT](https://arxiv.org/html/2403.10131)
- The CoT-with-quotes answer format adds +9.66 points on HotpotQA (25.62→35.28) and +14.93 on HuggingFace APIBench (59.07→74.00). It is slightly negative on Torch Hub (86.56→84.95). — [RAFT Table 2](https://arxiv.org/html/2403.10131)
- Headline: RAFT-7B HotpotQA 35.28 vs LLaMA2-7B+RAG 0.03 and domain-SFT+RAG 4.41. Domain fine-tuning without distractors (DSF) can get *worse* when retrieval is added (HuggingFace 61.06 DSF → 42.59 DSF+RAG). — [RAFT Table 1](https://arxiv.org/html/2403.10131)

**Making RALMs robust to irrelevant context (Yoran et al., Oct 2023; Llama-2-13B, QLoRA)**
- Random retrieved passages reduced accuracy on all 5 datasets tested, by more than 10 points on average for in-context RALM. — [arXiv 2310.01558](https://arxiv.org/html/2310.01558)
- Training recipe: each example's context is the top-1, a low-ranked, or a random passage "with equal probability". Datasets were small: 1,000 NQ examples; 2WikiMQA 500 questions (1,539 examples); StrategyQA 414 questions (1,584 examples). "Even 1,000 examples suffice to train the model to be robust to irrelevant contexts." — [arXiv 2310.01558](https://arxiv.org/html/2310.01558)
- Result: on NQ with random contexts, 33.8 vs 31.1 for the same model fine-tuned without retrieval. The robust 13B beat prompted Llama-2-70B on NQ top-1 (45.7 vs at most 42.4), so the authors conclude scale alone does not fix robustness. — [arXiv 2310.01558](https://arxiv.org/html/2310.01558)
- A training-free alternative is an NLI filter (BART-large-MNLI, 407M) that falls back to no-retrieval when entailment is below 0.5. It prevents harm but also discards helpful passages. — [arXiv 2310.01558](https://arxiv.org/html/2310.01558)

**ChatQA (NVIDIA, Jan 2024; Llama2 7B/13B/70B, Llama3 8B/70B)**
- Two stages. Stage 1 is about 128K general SFT samples. Stage 2 is "context-enhanced" tuning: context placed after the system prompt, conversational QA (7k human dialogues of about 5 turns each, plus 7k synthetic), single-turn QA sets, and the stage-1 data mixed back in. — [ChatQA, arXiv 2401.10225](https://arxiv.org/html/2401.10225)
- Ablations (70B, ChatRAG average): removing stage 2 dropped the score 54.14→43.22; removing stage 1 → 52.18; removing single-turn data → 52.25. — [ChatQA](https://arxiv.org/html/2401.10225)
- Unanswerable data was built by deleting the human-annotated relevant spans from the context, giving about 1.5k unanswerable turns. The target was always one fixed phrase: "Sorry. I cannot find the answer based on the context". — [ChatQA](https://arxiv.org/html/2401.10225)
- Dose-response on the answerable/unanswerable average (QuAC/DoQA): 1k→76.88, 1.5k→77.25, 2k→77.10, 2.5k→75.87. More unanswerable data stopped helping and then hurt. Synthetic unanswerable data was much worse than human-made (69.84), mainly on unanswerable accuracy. — [ChatQA Table 8](https://arxiv.org/html/2401.10225)
- Llama3-ChatQA-1.5 scored lower on unanswerables, which the authors attribute to answering from parametric knowledge when the context lacks the answer. — [ChatQA](https://arxiv.org/html/2401.10225)

**Self-RAG (Asai et al., Oct 2023; Llama2 7B/13B)**
- Adds reflection tokens: Retrieve (yes/no/continue), IsRel (relevant/irrelevant), IsSup (fully/partially/no support) and IsUse (5–1). The generator was trained on 150k instruction-output pairs labelled by a critic. The critic (Llama2-7B) was trained on 4k–20k GPT-4 labels per token type and reached above 90% agreement with GPT-4 on most types. — [Self-RAG HTML](https://arxiv.org/html/2310.11511)
- ASQA citation precision/recall: 66.9/67.8 at 7B and 70.3/71.3 at 13B. The authors report it beats ChatGPT and retrieval-augmented Llama2-chat on open-domain QA, reasoning and fact verification. — [Self-RAG HTML](https://arxiv.org/html/2310.11511); [abstract](https://arxiv.org/abs/2310.11511)

**RA-DIT (Meta, Oct 2023)**
- Two-stage dual instruction tuning; the LM stage "updates a pre-trained LM to better use retrieved information". The best model (65B) gains up to +8.9% 0-shot and +1.4% 5-shot on average over in-context RALM. — [RA-DIT abstract](https://arxiv.org/abs/2310.01352)

**Chain-of-Note (Tencent, Nov 2023; LLaMA-2 7B, ChatGPT-generated training data)**
- Training the model to write a short reading note per retrieved document before answering gave +7.9 EM on average when all retrieved documents were noise, and +10.5 rejection rate on real-time questions outside the model's knowledge. — [Chain-of-Note, arXiv 2311.09210](https://arxiv.org/abs/2311.09210)

**Trust-Align (Sep 2024; grounded refusal via DPO, includes sub-1B models)**
- 19K DPO pairs: question + documents (a mix of relevant and irrelevant) + chosen answer (GPT-4, grounded with citations, or a refusal when the documents are insufficient) + rejected answer. Rejected answers were sampled from an SFT model and labelled with five error types: *unwarranted refusal*, *over-responsiveness*, over-citation, improper citation, inaccurate claims. The top 50% by severity were kept. — [Trust-Align, arXiv 2409.11242](https://arxiv.org/html/2409.11242)
- DPO beat SFT in 26 of 27 configurations. Qwen-2.5-0.5B on ASQA went from 22.83 (in-context learning) to 54.76. Removing the refusal samples lowered Trust-Score by 10.2% (LLaMA-3-8b) and grounded-refusal F1 by 26.34%. — [Trust-Align](https://arxiv.org/html/2409.11242)
- Cost: Trust-Align models answer less often. LLaMA-3-8b's answered ratio on ASQA was 56.43% vs 99.05% for the baseline, and answer correctness improved in only 2 of 9 ASQA configurations. — [Trust-Align](https://arxiv.org/html/2409.11242)

**Position and length ("lost in the middle")**
- In LongMemEval, Llama 3.1 8B's QA accuracy "drops sharply beyond 3k retrieved tokens", while GPT-4o keeps improving past 20k. Even with oracle retrieval, a poor reading strategy cost up to 10 points absolute for GPT-4o. — [LongMemEval, arXiv 2410.10813](https://arxiv.org/html/2410.10813)
- ChatQA found sequential, reverse and "swing" orderings of the top-5 chunks performed about the same. — [ChatQA](https://arxiv.org/html/2401.10225)

### Inferences
- Maya's 1–5-line notes block is far below the roughly 3k-token range where small models degrade, so "lost in the middle" is unlikely to be the main cause of its failures. Training-data coverage is the more likely cause: inference questions, distractors, multi-turn context and perspective. This follows from LongMemEval's 3k-token finding and ChatQA's ordering result.
- Proposed SFT mix for the next Hanu round (retraining; no block change), adapting RAFT, RetRobust and ChatQA to 1–5-line notes:
  - About 45–55%: **needed note + 0–4 distractor notes**, with the needed note in a random position. Include many *implication* questions where the answer follows from the note without repeating its words: "peanut butter allergy" → "can I eat a PB&J?" → no, plus a reason.
  - About 15–20%: **distractor-only notes** (related but insufficient). Target: cannot_confirm. Make some distractors near misses: same relation, different person ("my brother Victor" when asked for the wife's name), or same topic, different attribute.
  - About 15–20%: **notes present but the request does not need them** (e.g. "set a timer"). Target: the normal plan, ignoring the notes. This trains "use notes only when needed".
  - About 10%: **no notes block**. Target: the normal plan, or cannot_confirm for personal-fact questions.
  - About 5–10%: **privacy/route contrast minimal pairs** (see Q4).
  - These shares are inferences from RAFT P≈60–80% and ChatQA's sweet spot. They are not measured for Maya and should be swept, e.g. distractor-only at 10/20/30%.
- Keep a single fixed abstention token or phrase (cannot_confirm), as ChatQA did. Mint unanswerables mainly by *deleting the answering note* from an otherwise answerable example rather than writing fresh unanswerables. ChatQA found this deletion-based construction worked better than synthetic unanswerables (77.25 vs 69.84).
- A RAFT- or Chain-of-Note-style "quote the note, then answer" field would probably help implication questions like the peanut case most (RAFT: +9.66 to +14.93 points from CoT with quotes). It requires a **block/grammar change plus retraining**: a `uses_note:` or `evidence:` slot in the plan language. A cheaper middle ground is a one-line `because: <quoted note>` before the answer, kept short (see Q5 on small models preferring short chains).

### Gaps
- RAFT's numeric P-sweep values exist only in its Figure 5; the text does not tabulate them.
- RA-DIT's LM fine-tuning data mix (how relevant and irrelevant chunks are combined) was not verified beyond the abstract.
- No paper found tests these recipes at about 2B on 1–5-line personal-fact contexts; every cited result is on 7B–70B except Trust-Align's 0.5B–3B runs.

## 2. Does the perspective or format of notes matter (first vs third person, key-value or triples, timestamps, source labels)? Studies on pronoun or persona confusion

### Takeaway
No study was found that directly measures first-person versus third-person memory-note confusion. Two strands of indirect evidence point the same way. The canonical persona-dialogue data uses first-person "I have a dog" lines to describe *the agent's own* persona. And attributing the context to a named third party ("Bob said ...") sharply increases faithfulness to that context in larger models, though the gain was not consistent for small models. Rewriting notes in third person ("The user has a peanut butter allergy") is wording-only and needs no block change, but it must be re-measured because the model was trained on the old wordings. Structured (JSON) formatting helped only when combined with an extract-then-reason reading step.

### Cited Findings
- PersonaChat ("Personalizing Dialogue Agents: *I have a dog, do you have pets too?*") conditions each speaker on a profile of at least 5 persona sentences, written in first person and describing that speaker. A second, rewritten set of the personas uses "rephrases, generalizations or specializations" to remove trivial word overlap as a shortcut. — [PersonaChat, arXiv 1801.07243](https://arxiv.org/pdf/1801.07243)
- A SIGIR 2021 study separated *self* personas from *partner* personas and found that modelling partner personas (previously neglected) improved response selection, i.e. models benefit when whose-persona-is-whose is made explicit. — [Partner Matters!, arXiv 2105.09050](https://ar5iv.arxiv.org/html/2105.09050)
- Context-faithful prompting (Zhou et al., Mar 2023) reframed the context as a third party's statement: `Bob said, "{c}" Q: {q} in Bob's opinion?`. On knowledge-conflict MRC (memorization ratio, lower is better), GPT-3.5 fell from 35.2 to 9.1 zero-shot (opinion + instruction), and to 3.0 with counterfactual demonstrations. LLaMA-2-7B-chat fell from 44.6 to 15.1. — [Context-faithful Prompting, arXiv 2303.11315](https://arxiv.org/html/2303.11315)
- The same reframing improved abstention on RealTime QA (no-answer accuracy): GPT-3.5 zero-shot rose from 30.6 to 83.3 (opinion) and 87.8 (opinion + instruction); LLaMA-2 rose from 14.3 to 36.7. However, "for smaller models, opinion-based prompts did not consistently improve selective prediction". — [arXiv 2303.11315](https://arxiv.org/html/2303.11315)
- LongMemEval on memory format: without Chain-of-Note, JSON did not consistently beat natural language; with Chain-of-Note, JSON "consistently helped readers of various capabilities". Replacing raw sessions with summaries or extracted facts generally *hurt* QA, except multi-session reasoning, where facts helped. — [LongMemEval](https://arxiv.org/html/2410.10813)
- LongMemEval's Chain-of-Note results for small models conflict within the paper. In the pilot (no JSON), Chain-of-Note hurt Llama 3.1 8B (0.454→0.420) and Phi-3.5-mini (0.342→0.324). Appendix E.1 says it "consistently improves the performance" of the small models tested in the final setting. — [LongMemEval](https://arxiv.org/html/2410.10813)
- LongMemEval sorts retrieved memory by timestamp before reading to help temporal consistency. Llama 3.1 8B struggled to extract time ranges and often invented one when the question had no time reference. — [LongMemEval](https://arxiv.org/html/2410.10813)
- A search for LLM studies of first-person vs third-person framing found only work on *narrator framing* in social and moral judgments, where first- vs third-person framing changed outputs substantially. — [arXiv 2604.23942](https://arxiv.org/pdf/2604.23942); [arXiv 2506.12657](https://arxiv.org/pdf/2506.12657)

### Inferences
- The measured Maya failure ("I have a peanut butter allergy, so I can't confirm that for you") matches what PersonaChat-style data would teach: in-context first-person lines are *the assistant's* persona. Recommendation, **wording only**: store and render notes in third person with the user as an explicit subject, e.g. `The user has a peanut butter allergy.`, or with a source label, e.g. `User said (2026-03-02): "I have a peanut butter allergy."` The second form mirrors the "Bob said" attribution that raised faithfulness in larger models. Because the small-model evidence is inconsistent, re-run the 12-wording test before adopting it.
- In the next training round (**retraining**), deliberately include *both* first-person and third-person note wordings with the same correct target. The model should treat "I" inside a note as the user and never as itself, which matters if users' own phrasings sometimes leak through. Add DPO rejected answers that make exactly the self-attribution error ("I have a peanut butter allergy, so ..."), with chosen = "You have a peanut butter allergy, so don't eat it."
- Use PersonaChat's "revised persona" trick for wording variance (the 5/12 result): for every fact, generate several paraphrased notes and several paraphrased or implication questions with low word overlap. Train on all of them so the model cannot key on string match.
- Prefer short natural sentences with an explicit subject over key-value or triple formats for a 2B reader. LongMemEval found JSON helped only with an extract-then-reason step (which Hanu's plan format lacks), and small-model gains from that step were inconsistent. A compact form like `User — allergy: peanut butter (said 2026-03-02)` should be A/B tested, not assumed better.
- Dates or "said on" labels inside a note line are wording-only and enable freshness resolution (Q3). Put dates in absolute form; LongMemEval shows small models mishandle time-range reasoning.

### Gaps
- No paper found directly measures pronoun or perspective confusion when first-person *user* statements are placed in a model's context. Neither was a study found of key-value vs sentence memory formats for models of 2B or smaller.
- The exact PersonaChat input prefix convention ("your persona:" / "partner's persona:") was not verified in fetched sources.

## 3. How to train correct behaviour under conflicting notes (old vs new fact) and uncertain (hedged or unconfirmed) notes

### Takeaway
Define a target behaviour for each conflict type and train or prompt for it explicitly. Freshness conflicts → use the newest fact (optionally mention the change). Genuine disagreement → state both. Insufficient → abstain. Making models aware of the conflict type gave large gains: Gemma 3 27B went from 59.4 to 76.2 on expected-behaviour accuracy. Models are highly receptive to coherent in-context evidence but show confirmation bias when evidence is mixed. Training with counterfactual or substituted entities reduces reliance on memorised answers. No direct study of training on hedged notes was found.

### Cited Findings
- The CONFLICTS benchmark (Google, Jun 2025; 458 queries) has five types with expected behaviours: *no conflict* → direct answer with no added uncertainty; *complementary* → consolidate; *conflicting opinions* → neutrally present both; *freshness/outdated* → "prioritize up-to-date information and may optionally acknowledge outdated sources"; *misinformation* → disregard the false source. — [CONFLICTS, arXiv 2506.08500](https://arxiv.org/html/2506.08500v2)
- Expected-behaviour accuracy, vanilla → taxonomy-aware prompt → oracle conflict type: Gemma 3 27B 59.4 → 76.2 → 87.6; GPT-4o 67.2 → 70.0 → 88.6. Average gains are about 5.5 points (taxonomy-aware) and about 9 (pipeline). Models identified the conflict type itself poorly (Gemma 3 27B 53.9%), and no fine-tuning was tested. — [CONFLICTS](https://arxiv.org/html/2506.08500v2)
- Knowledge-conflict study "Adaptive Chameleon or Stubborn Sloth" (May 2023): LLMs are "highly receptive to external evidence even when that conflicts with their parametric memory" when the evidence is coherent and convincing, but show strong confirmation bias when evidence mixes supporting and conflicting information. — [arXiv 2305.13300](https://arxiv.org/abs/2305.13300)
- Entity-based knowledge conflicts (Longpre et al., 2021): models over-rely on memorised answers when the passage contradicts them. Training with substituted entities reduces this, improves out-of-distribution generalisation by 4–7%, and helps on evolving, time-dependent queries. — [arXiv 2109.05052](https://arxiv.org/abs/2109.05052)
- Counterfactual demonstrations plus third-party attribution brought GPT-3.5's memorization ratio to 3.0 (from 35.2); demonstrations of plain factual examples gave limited or negative effects. — [arXiv 2303.11315](https://arxiv.org/html/2303.11315)
- FaithEval (Oct 2024; 4.9K problems covering unanswerable, inconsistent and counterfactual contexts): "even state-of-the-art models often struggle to remain faithful", and larger models are not necessarily more faithful. — [FaithEval, arXiv 2410.03727](https://arxiv.org/abs/2410.03727)
- A model trained with refusal data for time-sensitive questions refused them 66.8% of the time (SFT + refusals) vs 12.1% for SFT alone, showing that time-sensitivity handling is learnable from a few thousand examples (about 2k refusal + 2k contrast). — [Refusal Tokens, arXiv 2412.06748](https://arxiv.org/html/2412.06748v2)

### Inferences
- **Wording-only fix:** render a date on every note ("said 2026-03-02" or "as of March 2026") and render superseded facts explicitly where storage knows them, e.g. `The user used to live in Pune; since 2026-05 the user lives in Bengaluru.` This hands the model the resolution instead of asking a 2B model to infer it. The basis is CONFLICTS' oracle-type gains (+28 points for Gemma 3 27B) and small models' weak conflict-type detection.
- **Retraining:** add conflict examples with fixed targets:
  - Two dated notes on the same attribute → answer with the newer one (an optional "you changed this in May" is fine). Randomise which note appears first, so the model learns from dates rather than position.
  - Two undated, contradictory notes → cannot_confirm, or a clarify step if the plan language has one.
  - DPO rejected = picks the older fact, or blends both.
- **Hedged notes** ("The user might be vegetarian", "The user is thinking about moving"). Proposed targets: answer with the hedge preserved ("You mentioned you might be ..."); never state it as fact; cannot_confirm when the question demands certainty (e.g. "am I allergic?" from "may be allergic"). This is an inference by analogy to the CONFLICTS "no added uncertainty vs present both" behaviours, not a measured result.
- The "Victor" answer to "what is my wife's name" fits two documented mechanisms. Either the model is answering from memorised training-data entities (ChatQA's parametric-knowledge explanation, Longpre's memorisation), or it latched onto a near-miss distractor. Recommendations (**retraining**): never reuse a small pool of names across training rows; generate names from a large, diverse list (including Indian names, given the market); apply entity substitution so the same template appears with many names; and add near-miss distractor rows (other relatives' names) whose target is cannot_confirm. Check the v0.2.9 DPO set for name frequency; "Victor" recurring there would be a strong signal.

### Gaps
- No paper found trains models on *hedged or unconfirmed* in-context facts or measures the effect of hedge words in context.
- No fine-tuning result for the CONFLICTS taxonomy exists in the paper. The prompting gains are on 27B+ models, and transfer to 2B is unmeasured.
- LongMemEval's per-category results on knowledge-update questions for small models were not legible in the fetched text.

## 4. How to reduce generic refusals and dodges and over-refusal while keeping privacy refusals

### Takeaway
Refusal behaviour spreads from small amounts of refusal data (about 200 examples measurably raise refusal rates elsewhere). "Contrast" examples (benign look-alikes answered normally) are what contain the spread: contrast over-refusal fell from 0.318 to 0.182 when they were added. Per-category refusal tokens allow refusal rates to be tuned at decode time without retraining. DPO is effective for grounded refusal but can cut the answer rate sharply, and naive DPO can lower the likelihood of the *chosen* answer when chosen and rejected differ by only a few tokens. Privacy behaviour that depends on context (speaker vs earpiece) is best taught with minimal pairs that differ only in that context field.

### Cited Findings
- **Refusal Tokens** (Dec 2024; Llama-3 8B, also Llama-3.1 8B and Mistral-v0.3): a refusal token, or one token per category, is prepended to refusal responses in training. At inference its probability can be thresholded or logit-biased to steer refusal "without the need of any further fine-tuning". — [Refusal Tokens](https://arxiv.org/abs/2412.06748)
- On XSTest safe prompts, over-refusal was 16.4% with the token on vs 5.6% with it suppressed. Unsafe-prompt refusal dropped from 90.5% to 63.5% at the same time, so suppression trades safety for helpfulness. Category tokens gave 12.0% over-refusal with 88.5% unsafe refusal. — [Refusal Tokens Table 5](https://arxiv.org/html/2412.06748v2)
- Contrast data matters most. Refusal-only training gave 0.318 refusal on benign contrast prompts; refusal + contrast gave 0.182 (0.116 with category tokens). Training data was about 10k refusal and about 1k contrast examples. "Even about 200 refusal messages increased refusal rates" on other sets, and refusal-only training raised TriviaQA refusals from about 0% to about 15%. — [Refusal Tokens](https://arxiv.org/html/2412.06748v2)
- **DPO failure mode (DPOP / Smaug, Feb 2024):** standard DPO "can lead to a reduction of the model's likelihood of the preferred examples", "especially [on] datasets in which the edit distance between pairs of completions is low". DPO-Positive adds a term to prevent this. — [DPOP, arXiv 2402.13228](https://arxiv.org/abs/2402.13228)
- Safety DPO can make models "memorize refusal boilerplate" and decline benign requests, overfitting to refusal phrases in preferred responses (evaluated on OR-Bench). This comes from a search-result summary; the paper was not fetched. — [arXiv 2502.13603](https://arxiv.org/pdf/2502.13603)
- Trust-Align explicitly labels *unwarranted refusal* and *over-responsiveness* as separate error types in its rejected answers. Even so, its DPO models answered far less often (56% vs 99%). — [Trust-Align](https://arxiv.org/html/2409.11242)
- Over-refusal resources: XSTest has 250 safe prompts that look unsafe; OR-Bench has about 80k seemingly toxic prompts plus a hard subset of about 1k (as described in later papers). — [FalseReject, arXiv 2505.08054](https://arxiv.org/pdf/2505.08054); [DDOR, arXiv 2606.03601](https://arxiv.org/html/2606.03601v1)
- FalseReject (COLM 2025): 16k seemingly toxic queries across 44 categories with structured-reasoning responses. SFT on it "substantially reduces unnecessary refusals" without hurting safety; over-refusal persisted across all 29 LLMs benchmarked. — [FalseReject](https://arxiv.org/abs/2505.08054)
- A contrastive-refinement method for over-refusal was evaluated on Qwen2.5-1.5B, Qwen2.5-7B and LLaMA-3-8B, using 250 XSTest-style prompts plus 500 toxic prompts. This comes from a search-result summary; the paper was not fetched. — [arXiv 2603.03323](https://arxiv.org/pdf/2603.03323)
- **Contextual privacy:** reasoning about contextual integrity plus RL on about 700 synthetic examples "substantially reduces inappropriate information disclosure" while keeping task performance, with transfer to the human-annotated PrivacyLens benchmark. — [arXiv 2506.04245](https://arxiv.org/abs/2506.04245)

### Inferences
- The "I can't help with that right now, but I can help with other things" dodge and the "secret" refusal on earpiece are consistent with documented refusal spillover and boilerplate overfitting. Audit v0.2.9 (999 pairs) for: (a) how often the chosen side is a refusal or cannot_confirm vs a grounded answer; (b) whether the dodge phrase appears as a chosen response anywhere; (c) chosen/rejected edit distance. Many minimal-edit pairs (answer vs cannot_confirm) are exactly the regime where DPOP says DPO lowers chosen likelihood.
- DPO data additions (**retraining**):
  - Hard negatives where rejected = the generic dodge, rejected = cannot_confirm when the note *does* answer, rejected = "secret" refusal on earpiece, and rejected = self-attribution of the note. Chosen = the grounded answer in each case.
  - Mirror pairs in the other direction (rejected = an answer invented beyond the notes; rejected = speaking a private fact aloud on speaker without confirmation), so DPO does not simply shift mass toward answering.
  - Use DPOP, or add an SFT/NLL term on the chosen answer (an inference from DPOP's finding), because many pairs will differ by a few tokens.
- **Minimal-pair privacy data (retraining):** for each private-fact question, emit 2–3 rows that differ only in `AUDIO_ROUTE` (earpiece → answer; speaker → confirm first) and only in note sensitivity (health or money vs a favourite colour). This is the contrast-set principle applied to the route field. Budget: hundreds to low thousands of rows, by analogy to about 700 CI examples and about 1k contrast examples. Keep refusal or confirm rows a minority, given the about-200-example spillover finding.
- **No-retraining lever:** the plan language already has categorical reasons (`secret`, `cannot_confirm`), which work like Refusal Tokens' category tokens. If Hanu decodes with a GBNF grammar in llama.cpp, a logit bias against the first token of `secret` when `AUDIO_ROUTE` is earpiece, or a small negative bias on the dodge prefix, can be tried at decode time. This is an inference, and it must be validated against leak rate (Refusal Tokens showed suppression also lowers correct refusals: 90.5%→63.5%).
- **Evaluation:** add a Maya-specific over-refusal set (benign memory questions about health, family and money on earpiece) next to the privacy-leak set, and track both together. Refusal rate alone is a weak safety proxy.

### Gaps
- No paper found does DPO with over-refusal hard negatives specifically on a model of about 2B or smaller with a measured before and after. Trust-Align (0.5B–8B) is the closest.
- Numeric gains for FalseReject SFT, contrastive refinement, contextual-integrity RL and DPOP vs DPO were not in the fetched abstracts.
- Logit bias on structured-output reason tokens under a grammar has no published evaluation; it is an untested analogy to Refusal Tokens.

## 5. How much data a 2B vs a 270M model needs; whether teacher distillation helps; effects of curriculum and multi-turn context on note-following

### Takeaway
Grounding and robustness behaviours are learnable from small datasets at 7–13B: about 1k examples for robustness to irrelevant context, about 1.5k unanswerables, and about 19k DPO pairs for grounded refusal. Sub-1B models can improve a lot (Qwen2.5-0.5B: 22.83→54.76 with Trust-Align), but there is no controlled data-size study for 270M. Distilling rationales from a teacher helps small models, but models of 3B or smaller learn better from *short* reasoning than from long teacher chains. Multi-turn context is a distinct failure: LLMs lose an average of 39% in multi-turn settings, and ChatQA's gains came from explicit multi-turn context training. Maya's "earlier turn → ignores notes" failure most likely calls for training rows that contain conversation history.

### Cited Findings
- Robustness to irrelevant context from about 1,000 NQ examples (13B, QLoRA, 5 epochs). — [arXiv 2310.01558](https://arxiv.org/html/2310.01558)
- About 1.5k unanswerable turns was the best amount (2.5k was worse). — [ChatQA](https://arxiv.org/html/2401.10225)
- 19K DPO pairs. Trained sizes included Qwen-2.5 0.5B–7B and LLaMA-3.2 1B/3B; 0.5B ASQA rose from 22.83 to 54.76, and LLaMA-3.2-3b DPO gained +6.70 over SFT on ASQA. — [Trust-Align](https://arxiv.org/html/2409.11242)
- Self-RAG used 150k generator examples (7B/13B). — [Self-RAG](https://arxiv.org/html/2310.11511)
- About 200 refusal examples are enough to shift refusal behaviour elsewhere. — [Refusal Tokens](https://arxiv.org/html/2412.06748v2)
- **Distillation:** Distilling Step-by-Step (2023) trained a small model on LLM-extracted rationales as an extra multi-task signal. A 770M T5 outperformed few-shot 540B PaLM using 80% of the data, while standard fine-tuning failed even with 100%. — [arXiv 2305.02301](https://arxiv.org/abs/2305.02301)
- "Small Models Struggle to Learn from Strong Reasoners" (2025): models of 3B or smaller "don't reliably benefit from long chain-of-thought reasoning or from distillation from larger models" and do better with "shorter, simpler reasoning chains". *Mix Distillation*, which blends long and short chains or large- and small-teacher outputs, beats either source alone. — [arXiv 2502.12143](https://arxiv.org/abs/2502.12143)
- RAFT's CoT targets were generated by GPT-4 (teacher distillation into 7B). — [RAFT](https://arxiv.org/html/2403.10131)
- **Curriculum / staging:** ChatQA's two stages (general SFT, then context-enhanced) were both needed: no stage 1 → 52.18, no stage 2 → 43.22, both → 54.14. — [ChatQA](https://arxiv.org/html/2401.10225)
- **Multi-turn:** an "average drop of 39% across six generation tasks" from single-turn to multi-turn across all top models tested. The authors attribute it mostly to unreliability: models make premature assumptions in early turns and then over-rely on them ("get lost and do not recover"). — [LLMs Get Lost in Multi-Turn Conversation, arXiv 2505.06120](https://arxiv.org/abs/2505.06120)
- ChatQA trained on multi-turn conversational QA (human dialogues averaging about 5 turns; synthetic about 4.4) and encoded the dialogue history together with the current query. — [ChatQA](https://arxiv.org/html/2401.10225)
- **270M:** Google positions Gemma 3 270M as a base whose "true power is unlocked through fine-tuning", for tasks like text classification and data extraction. An IFEval figure of 51.2% is reported by secondary sources and is unverified. — [Google Developers Blog](https://developers.googleblog.com/en/introducing-gemma-3-270m/)

### Inferences
- **2B data budget (inference from the above):** about 3k–10k SFT rows covering the Q1 mix, plus about 3k–5k DPO pairs. The current 999 pairs are small relative to Trust-Align's 19k, but in the range where RetRobust and ChatQA saw effects. Prioritise *diversity* (names, note wordings, implication questions, routes, histories) over volume. Mix general and planning data back in (ChatQA's stage-1 replay) so that plan-writing skill does not regress.
- **270M:** the measured gap (8 privacy leaks in 50 vs 1; wrong names) is consistent with the learnability gap. Recommendations:
  - (a) Distil from the fine-tuned 2B or a larger teacher with *short* targets, not long rationales.
  - (b) Give it more rows per behaviour than the 2B. Trust-Align's 0.5B gains suggest DPO helps at that scale, but this is extrapolation with no 270M evidence.
  - (c) Consider gating privacy in code (deterministic route check) rather than trusting a 270M model with it.
  - (d) Restrict it to narrow sub-tasks (e.g. note relevance classification), which is where Google positions it.
- **Multi-turn fix (retraining; history is already part of Hanu v4's input):** in 30–50% of note-bearing rows, prepend 1–4 prior turns. Some are unrelated; some mention a different fact; some contain an earlier cannot_confirm answer *that the new notes now resolve*. The target must still use the current notes. Add DPO pairs where rejected = repeating the earlier turn's cannot_confirm. This directly targets the "over-rely on earlier answers" mechanism.
- **Teacher pipeline:** generate candidate plans with a large teacher. Verify each with a checker (does the answer follow from the notes; is the route rule respected), and take rejected samples from the current Hanu v4's *own* failures (Trust-Align built its negatives from its SFT model's real errors). On-policy negatives target the dodges the model actually produces.
- **Curriculum:** the only staged evidence is ChatQA's two stages. A reasonable order is general planning SFT, then note-grounding SFT with history and distractors, then DPO on hard negatives. This is supported only by ChatQA's ablation, not by a small-model curriculum study.

### Gaps
- No controlled study was found of how grounding or abstention data size scales at 270M vs 2B.
- No paper was found that evaluates distillation from a fine-tuned 2B into a 270M student for structured plan output.
- No small-model curriculum study (ordering of SFT stages for context use) was found.
- Gemma 4 E2B-specific RAG or fine-tuning guidance was not found; the Gemma 3 270M IFEval number is unverified.
